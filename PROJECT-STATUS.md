# PROJECT STATUS — POS Контроль

> Документ для моделей и разработчиков: что это за проект, в каком он состоянии, что открыто и как продолжать.
> Обновляйте раздел «Журнал» при каждом значимом изменении. Последнее обновление: **26.11.2026**.

## 1. Что это

POS-система для сети магазинов (5 точек: Керуен, Sky, My Kids, Dalida Plaza, Elegant Park).
Продажи, расходы, прибыль, товары, склад, поставки, рабочее время продавцов, аналитика.
Офлайн-first: устройство работает без интернета, при подключённом сервере — общая база через Cloudflare.

- **Версия: 3.4.12** (версия задаётся в `app/src/core.js` → `APP_CONFIG.version`, `app/ios-build/core.js`, `app/src/sw.js`)
- Продукт готов к эксплуатации: сборки под Windows, Android, iPhone (PWA), веб.
- Язык интерфейса и документации — русский.

## 2. Технический стек

| Слой | Что используется |
|---|---|
| Фронтенд | чистый JS, ES5-совместимый синтаксис, без сборщиков, без npm-зависимостей во время работы, без CDN |
| Хранение | `localStorage` (ключ `poskontrol_db_v1`), резервная копия в JSON, фото сжимаются в canvas (~720 px) |
| Excel | собственный генератор `xlsx.js` (ZIP без сжатия + SpreadsheetML, CRC32), настоящие `.xlsx` |
| Пароли | PBKDF2/`pbkdf2$…` на сервере, SHA-256 через Web Crypto (fallback FNV) локально |
| Android | Capacitor + нативная WebView-оболочка `app/android-build` (сборка APK без Gradle: aapt2 → javac → d8 → zipalign → apksigner) |
| Windows | Electron `app/desktop` (electron-builder), данные в `%APPDATA%/POS Контроль` |
| iOS | PWA: `manifest.json` + service worker, установка «На экран „Домой“» из Safari |
| Бэкенд | Cloudflare Worker `pos-kontrol-api` + D1 `poskontrol` |
| Тесты | Puppeteer в реальном Chromium (`app/test/*.js`) |

## 3. Инфраструктура (значения — не секреты)

| Параметр | Значение |
|---|---|
| Адрес API | `https://pos-kontrol-api.my-tt-accaunt235.workers.dev` |
| Проверка | `GET /api/health` → `{"ok":true,"app":"POS Контроль API","version":"1.0.0","hasSecret":true}` |

| Коллекции | `users`, `points`, `categories`, `products`, `stock`, `supplies`, `sales`, `saleChanges`, `expenses`, `time`, `stockChecks`, `settings` |
| Токен входа | 30 дней, лимит тела запроса 2 МБ |
| Секрет `JWT_SECRET` | значение — в `docs/cloudflare/ДАННЫЕ-ДЛЯ-CLOUDFLARE.md` и в Cloudflare → Worker → Settings. **Менять нельзя** без перерегистрации сотрудников |

⚠️ Не выполнять `wrangler deploy` из `app/cloudflare` — в `wrangler.toml` заглушка `database_id`,
деплой затрёт рабочую привязку. Всё менять через панель Cloudflare, затем **Deploy** (без Deploy привязки и секреты не применяются).

## 4. Где какой код

| Путь | Роль |
|---|---|
| `app/src/` | **исходники PWA** — здесь вносятся изменения в логику и интерфейс |
| `app/ios-build/` | **готовая к хостингу сборка**: тот же код + `vercel.json`, `_headers`, `_redirects`, `sw.js`, `icons/`. Содержимое идентично `src/` (проверено `diff -rq`) |
| `app/web/` | генерируется `build.py` из `src/` — не хранится в репозитории |
| `app/test/` | сквозные тесты (e2e, финансы, склад/поставки, права, облако, десктоп, PWA) |
| `app/cloudflare/` | копия кода Worker + схема; **эталон для правок сервера — `db/`** |
| `db/` | `worker.js`, `schema.sql`, `СХЕМА-БД.sql`, `Сотрудники-в-базу.sql`, `cloudflare-users.sql` |
| `builds/` | готовые артефакты (apk, html, iOS-архив); `.exe` — в GitHub Releases |
| `docs/` | инструкции, перенесённые с Google Диска |
| `data/from-old-system/` | выгрузки старой системы: склад по дням (`.xlsx`), CSV товаров, скриншоты |

**Важно при правках:** после изменения `app/src/*` нужно синхронизировать `app/ios-build/`
(это копия) и поднять версию в `core.js` + `sw.js`, иначе PWA отдаст старый кэш.

## 5. Что готово (проверено)

- Все разделы: панель, касса, товары, склад, поставки, точки, пользователи, время, аналитика, помощь, настройки.
- Роли и права: продавец не видит аналитику/товары/точки и работает только со своими точками; последнего админа удалить нельзя.
- Оплаты: наличные, Kaspi QR (обязательное фото чека), смешанная — с разбивкой сумм.
- Экспорт в настоящий Excel с несколькими листами, автофильтрами и шапкой.
- Тёмная тема, мобильный интерфейс (нижняя навигация, bottom-sheet), десктопный интерфейс (Ctrl+K, Alt+1…9, F11).
- Синхронизация Cloudflare: офлайн-очередь, автосинхронизация, статус в шапке, аудит-лог.
- Импорт из CSV (пользователи, товары, история), импорт данных старой системы.
- Тесты: заявлено **31/31 e2e-проверок, 0 ошибок JS** (`npm run test:e2e`), отдельно — `test/apk-assets.js`, работа в песочнице без `localStorage`, открытие `dist/index.html` через `file://`.
- Сборки 3.4.12: Windows `.exe` (74 МБ), Android `.apk` (487 КБ), iOS-архив для хостинга, одиночный `.html` (837 КБ).

## 7. Как проверять и собирать

```bash
cd app
python3 build.py                 # web/ + dist/index.html
npm run serve                    # локальный сервер :8080 (нужен для service worker)
npm run test:e2e                 # 31 проверка в Chromium
npm run test:sandbox             # песочница без localStorage
bash android-build/build_apk.sh  # APK (нужен KEYSTORE_PASS)
bash desktop/build-windows.sh    # Windows .exe
```

## 8. Правила для моделей

1. **Секреты хранятся в репозитории осознанно** — `JWT_SECRET`, пароли сотрудников, ключ подписи APK. Не удалять и не «санитизировать» их: так решил владелец. Все значения — в [SECURITY.md](SECURITY.md).
2. **Не переписывать историю** и не удалять `data/from-old-system` — это исходные данные для сверки.
3. **Не деплоить** Cloudflare из CLI без явного разрешения владельца (затрёт привязку D1).
4. Меняя поведение — обновлять этот файл (раздел «Журнал») и версию в `core.js`/`sw.js`.
5. Документация на русском, стиль — простой язык, без жаргона: её читают продавцы и владелец.
