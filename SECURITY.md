# Безопасность: что намеренно не попало в репозиторий

Репозиторий **публичный**. При переносе с Google Диска из файлов удалены секреты и персональные данные.
Ниже — что именно вырезано и где лежит оригинал.

| Что | Где оригинал | Что сделано в репозитории |
|---|---|---|
| `JWT_SECRET` (секрет Cloudflare Worker, подписывает токены входа) | Cloudflare → Workers → `pos-kontrol-api` → Settings → Variables and Secrets; копия — Google Диск, папка «3. База и Cloudflare» | В `docs/cloudflare/ДАННЫЕ-ДЛЯ-CLOUDFLARE.md` и `ШАГИ-CLOUDFLARE.md` значение заменено на `<ВСТАВЬТЕ-СЕКРЕТ>` |
| Пароли 33 сотрудников (`сотрудники-логины.csv`) | Google Диск, папка «3. База и Cloudflare» | В репозитории только формат: `docs/team/сотрудники-логины.example.csv` с заглушками. Таблица логинов/паролей в `docs/team/Сотрудники-инструкция.md` убрана |
| Ключ подписи APK `poskontrol.keystore` + пароль хранилища | Google Диск, архив `pos-app-source-3.4.12.zip` → `android-build/poskontrol.keystore`; пароль — в том же архиве | Файл ключа не закоммичен. `app/android-build/build_apk.sh` берёт пароль из переменной окружения `KEYSTORE_PASS` (`--ks-pass env:KEYSTORE_PASS`) |

## Как собрать APK, если понадобится

```bash
# положить ключ рядом со скриптом (файл не попадёт в git — см. .gitignore)
cp /путь/к/poskontrol.keystore app/android-build/
export KEYSTORE_PASS='пароль-из-архива-на-Диске'
bash app/android-build/build_apk.sh
```

## Почему нельзя менять JWT_SECRET «на всякий случай»

Пароли сотрудников хэшируются с участием этого секрета. Если его сменить, **все существующие аккаунты
перестанут пускать** — придётся очищать `records` в D1 и регистрироваться заново.

## Если репозиторий станет приватным

Скажите — тогда можно вернуть в него ключ подписи и полный `сотрудники-логины.csv`, чтобы всё лежало в одном месте.

## Что ещё стоит проверить владельцу

- `JWT_SECRET` уже был опубликован в открытом виде в документах на Google Диске — имеет смысл
  **сменить его тогда, когда будете готовы перерегистрировать сотрудников** (см. предупреждение выше).
- Пароли сотрудников совпадают с логинами (например, логин `ivanova_1` и пароль `ivanova_1`) — это слабо,
  стоит попросить продавцов сменить пароль в приложении (Настройки → сменить пароль).

## Важно про файлы `db/Сотрудники-в-базу.sql` и `db/cloudflare-users.sql`

В них лежат ФИО, логины и PBKDF2-хэши паролей всех 33 сотрудников. Это нужно для рабочего импорта в D1,
поэтому файлы оставлены в репозитории. Но: пароли сотрудников **совпадают с логинами**, то есть по этим файлам
теоретически можно подобрать доступ.

**Поэтому репозиторий настоятельно рекомендуется сделать приватным** (Settings → General → Danger Zone →
Change visibility → Private). Если репозиторий остаётся публичным — смените пароли продавцам
(Настройки → сменить пароль) и попросите поставить `JWT_SECRET` заново при следующей перерегистрации.

Файл `пользователи (1).csv` с паролями в открытом виде в репозиторий **не попал** — он есть только на Google Диске.
