# Cloudflare: общая база и синхронизация

Приложение работает офлайн на каждом устройстве, а с подключённым сервером данные
(точки, товары, склад, продажи, расходы, время, пользователи, настройки) автоматически
расходятся по всем устройствам через Cloudflare Workers + D1.

```
Телефон продавца ─┐
Телефон владельца ─┼─► https://pos-kontrol.<аккаунт>.workers.dev ─► D1 (SQLite)
Компьютер ────────┘        (Cloudflare Worker, бесплатный план)
```

Что нужно: аккаунт Cloudflare (бесплатный) и 10–15 минут.

---

## Вариант 1. Через веб-панель (без установки программ)

### 1. База D1
1. Зайдите на https://dash.cloudflare.com → **Storage & Databases → D1 SQL Database**.
2. **Create database**, имя: `poskontrol`, регион — ближайший (например, EEU / Western Europe).
3. Откройте базу → вкладка **Console**.
4. Скопируйте содержимое файла `cloudflare/schema.sql` и выполните все запросы
   (по одному, если консоль не принимает скрипт целиком: `records`, затем `meta`, затем `audit_log`, затем индексы).
   Должно появиться 3 таблицы: `records`, `meta`, `audit_log`.
5. Скопируйте **Database ID** — он понадобится только для варианта с wrangler.

### 2. Worker (API)
1. **Workers & Pages → Create → Worker**, имя: `pos-kontrol-api`.
2. **Deploy**, затем **Edit code** (или «Quick edit»).
3. Удалите шаблон и вставьте целиком файл `cloudflare/worker.js` → **Deploy**.
4. Адрес API появится в виде `https://pos-kontrol-api.<ваш-аккаунт>.workers.dev`.

### 3. Привязка базы к Worker
1. Worker → **Settings → Bindings → Add → D1 Database**.
2. Variable name: **`DB`** (ровно так), Database: **`poskontrol`** → Save.

### 4. Секрет для токенов
1. Worker → **Settings → Variables and Secrets → Add**.
2. Тип **Secret**, имя **`JWT_SECRET`**, значение — длинная случайная строка (32+ символа,
   например сгенерируйте на https://random.org или вставьте 40 случайных букв/цифр).
3. Save, затем **Deploy** ещё раз, чтобы настройки применились.

### 5. Проверка
Откройте в браузере `https://pos-kontrol-api.<аккаунт>.workers.dev/api/health`.
Ожидаемый ответ:

```json
{"ok":true,"app":"POS Контроль API","version":"1.0.0","users":0,"hasSecret":true}
```

Если `users: -1` — не привязана база (шаг 3). Если `hasSecret: false` — не задан `JWT_SECRET` (шаг 4).

## Вариант 2. Через wrangler (быстрее для тех, кто дружит с терминалом)

```bash
cd pos-app
npm install -D wrangler@4

npx wrangler login                        # откроется браузер, вход в Cloudflare
npx wrangler d1 create poskontrol         # выдаст database_id
```

Вставьте `database_id` в `cloudflare/wrangler.toml` вместо заглушки `00000000-0000-...`.

```bash
npx wrangler d1 execute poskontrol --remote --file=cloudflare/schema.sql
npx wrangler secret put JWT_SECRET --config cloudflare/wrangler.toml   # введите строку
npx wrangler deploy --config cloudflare/wrangler.toml
```

`wrangler.toml` уже содержит привязку `DB` и имя Worker `pos-kontrol-api`.
Проверка — тот же `/api/health`.

## Подключение приложения

1. Откройте приложение → на экране входа нажмите **«Подключить сервер»**
   (или позже: **Настройки → Сервер и синхронизация**).
2. Вставьте адрес `https://pos-kontrol-api.<аккаунт>.workers.dev` → **Проверить связь**.
   Должно появиться «Сервер доступен».
3. **Сохранить**, затем:
   - новый бизнес → «Создать аккаунт на сервере»;
   - уже есть аккаунт → ввести логин и пароль и нажать «Войти».
4. Кнопка **«Синхронизировать»** отправит локальные данные на сервер (или заберёт их оттуда).

Дальше всё автоматически: после каждого изменения (продажа, расход, приход товара) данные
уходят на сервер через 2–3 секунды, а также каждые 60 секунд и при появлении интернета.
Значок облака в шапке показывает состояние: облако — всё синхронизировано, оранжевая
стрелка с числом — есть неотправленные записи, красный — ошибка (нажмите на значок).

### Роли

| Кто регистрируется | Роль | Доступ |
|---|---|---|
| 1-й на сервере | **Администратор** | всё, включая пользователей и настройки |
| 2-й | **Разработчик** | аналитика, товары, склад, точки; без кассы (продаж и расходов) |
| 3-й и далее | **Продавец** | касса своих точек, свои продажи/расходы/время |

Сотруднику можно назначить несколько точек (Точки продаж → Пользователи → «Точки продаж» — отметить
несколько). Продавец переключается между ними в шапке приложения; касса, склад и отчёты при этом
показывают только выбранную точку. Сервер проверяет, что продавец пишет только на свои точки.

Роль назначается сервером по счётчику пользователей — на всех устройствах она одинаковая.
Продавцов создаёт администратор: **Точки продаж → Пользователи → Создать пользователя**
(при подключённом сервере пароль сразу сохраняется в облаке, и сотрудник может войти
со своего телефона).

## Как устроена синхронизация

- Каждая запись имеет `updatedAt`; сервер хранит последнюю версию (`records.data`), а удаления — «надгробия» (`deleted_at`).
- Клиент отправляет только изменённое с прошлой синхронизации (по курсору `lastSync`).
- Конфликты решаются по времени изменения: более новая версия побеждает.
- Офлайн: изменения остаются в локальной базе и в очереди; при появлении сети уходят автоматически.
- Сервер проверяет права: продавец не может менять товары/точки/пользователей и чужие продажи;
  в его продажи сервер принудительно записывает его `userId` и точку.
- Пароли: PBKDF2-SHA256 10 000 итераций + HMAC-«перец» из `JWT_SECRET`, соль на пользователя;
  токен JWT живёт 30 дней. Подбор ограничен: 8 неудачных попыток за 15 минут блокируют вход.
  **Не меняйте `JWT_SECRET` после первых регистраций** — пароли перестанут подходить.
- Локальная резервная копия (Настройки → «Скачать копию JSON») остаётся рабочим способом бэкапа.

### Ограничения

- Бесплатный тариф Workers даёт 10 мс CPU на запрос — код под это подогнан: короткая растяжка пароля,
  не больше 300 записей на коллекцию за проход, пакет синхронизации обрезается до ~500 КБ
  (остальное уходит следующими проходами автоматически).
- За один проход сервер отдаёт до 1200 записей; остальное добирается следующими проходами.
- Если на новом устройстве сначала загрузили демо-данные, перед подключением к серверу
  лучше сделать «Сбросить все данные» в настройках — иначе демо-записи уйдут в общую базу.

## Обслуживание

```bash
# обновить код API после изменений
npx wrangler deploy --config cloudflare/wrangler.toml

# резервная копия облачной базы
npx wrangler d1 export poskontrol --remote --output backup-$(date +%F).sql

# журнал действий (входы, регистрации, смены паролей, синхронизации)
npx wrangler d1 execute poskontrol --remote --command "SELECT created_at, user_name, action FROM audit_log ORDER BY created_at DESC LIMIT 30"
```

В веб-панели то же самое: D1 → Console (SQL), Worker → Deployments (история версий и откат).

## Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| «Нет связи с сервером» | неверный адрес (нужен `https://…workers.dev`, без `/api`), Worker не задеплоен, блокировка сети |
| «На сервере не задан JWT_SECRET» | шаг 4 не выполнен или не сделан Deploy после добавления секрета |
| «Не подключена база D1» | привязка `DB` отсутствует или названа иначе |
| `users: -1` в `/api/health` | таблицы не созданы — выполните `schema.sql` |
| «Это имя пользователя уже занято» | логин занят в облаке — выберите другой или войдите под ним |
| «Неверное имя пользователя или пароль» | пароль облака отличается от локального; вход по локальным данным работает офлайн |
| Синхронизация «зависла» на числе | нет прав на эти записи (например, продавец пытается менять товары) — записи останутся локальными |

Локальная проверка без Cloudflare (для разработки):

```bash
cd pos-app/cloudflare
npx wrangler d1 execute poskontrol --local --file=schema.sql
npx wrangler dev --local --port 8787 --ip 0.0.0.0
# в приложении укажите http://127.0.0.1:8787
```
